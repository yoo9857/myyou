# 순서와 비용 — 다음 영화에 그대로 적용

이 문서는 The Devil All The Time 제작에서 **실제로 발생한 낭비와 결함**을 하나씩 규칙으로
바꾼 것이다. 각 항목은 "무엇이 잘못됐고, 무엇이 그것을 막는가"로 되어 있다.

## 첫 번째 규칙 — 무료가 전부 끝나기 전에는 돈을 쓰지 않는다

이 파이프라인에서 **실행할 때마다 돈이 드는 것은 두 개뿐**이다.

| 단계 | 비용 |
|---|---|
| `narration_pass.py generate` | codex 호출 (약 70k 토큰) |
| `generate_narration_audio.py` | ElevenLabs 문자 수 |

반대로 **결과의 품질을 결정하는 것은 전부 무료**다 — 스토리맵, 사건 순서, 해설 위치,
구간 경계, 미리보기. 몇 번을 다시 만들어도 비용이 0이다.

Devil은 이 순서를 거꾸로 했다. 대본을 네 번, 음성을 여러 번 생성했는데 **구조 결함이
매번 유료 작업 뒤에 발견**됐기 때문이다. 아래는 그때 발견된 것들이고, 전부 API 호출
없이 찾을 수 있었던 것이다.

- 그룹마다 원음 사건이 앞으로 몰려 **대치 장면이 목사 사망보다 먼저** 10분 38초에 재생
- 콜드 오픈으로 지정한 사건이 세 번째로 밀림
- 해설 49줄 중 **33줄이 영화 대사 위에** 얹힘 (다수가 84~98%)
- 구간 경계가 대사 중간을 자름 — 끝에서 42회, 시작에서 44회
- 해설이 빠진 블록 9개가 음성 없이 영화 소리만 줄어든 채 7초씩 재생

**강제 장치**: `scripts/run_workflow.py`가 유료 단계 앞에서 멈춘다. 사람이 미리보기를
보고 `approve structure`를 실행해야 열린다. 승인은 편집표의 지문(사건·순서·타임코드)에
묶이므로, 편집표가 바뀌면 승인이 자동으로 무효가 된다.

```
python scripts/run_workflow.py <project>/config.json run      # 미리보기까지 무료로 진행
python scripts/run_workflow.py <project>/config.json approve structure
python scripts/run_workflow.py <project>/config.json run      # 대본·음성부터 이어서
```

## 두 번째 규칙 — 자막은 화면 내용을 알려주지 않는다

사건 타임코드를 자막에서만 잡으면 **33개 중 12개가 틀린다**. 실제로 그랬다. 자막은 누가
말하는지만 알려주고, 이 영화는 핵심 장면이 대사 없이 지나간다.

- 거미 설교는 자막상 11분에 끝나지만 항아리를 붓는 것은 **14분 30초**
- 헬렌이 죽는 장면은 자막의 "Resur--"(39분 43초)보다 **2분 앞선 37분 40초**
- `carl_method`는 68분으로 잡혀 있었지만 실제로는 **43분**

**절차**: 자막에서 앵커 대사로 대략을 잡고, 그 주변을 15~30초 간격으로 프레임 추출해
눈으로 확정한다. `needs_visual_review`는 프레임을 실제로 본 뒤에만 내린다.

```
python <project>/verify_intervals.py                    # 최초 1회 전체
python <project>/verify_intervals.py jack_sacrifice ... # 수정 후 바뀐 것만
python <project>/verify_intervals.py 28:40 29:15        # 위치 탐색
```

**하나 고칠 때마다 전체를 다시 뽑지 말 것.** 33장을 재추출하고 시트 4장을 다시 읽는
비용은 수정 자체의 여덟 배이고, 나머지 32장은 직전과 동일하다.

## 세 번째 규칙 — 약속 구간과 장면 범위는 다르다

`source_start`/`source_end`는 편집기가 **잘라 쓸 수 있는 범위**이고,
`selected_intervals`는 **반드시 화면에 나온다는 약속**이다. `validate_story_coverage`가
약속의 85% 이상이 실제로 쓰였는지 검사한다.

둘을 같게 놓으면 반드시 실패한다. 19분 리뷰가 40분치 원본을 다 담을 수 없다.

크기는 **그 사건이 실제로 받는 블록에 맞춰** 정한다. 커버리지는 `쓰인 길이/약속 길이`라
고정된 손실은 약속이 작을수록 비율이 커진다.

- 해설 사건: 해설 7초 + 뒤따르는 영상 구간 → **16~18초** 약속
- 원음 전담 사건: 블록 하나뿐 → **10초** 약속, `DIALOGUE_BLOCK_MIN`은 13초 이상

약속의 시작점은 **편집기가 실제로 클립을 여는 지점**에 맞춘다. 대사 중간에서 시작하는
윈도우는 뒤로 밀리므로, 약속도 같은 규칙으로 밀어야 한다.

## 네 번째 규칙 — 구간 경계가 대사를 자르면 안 된다

예산 계산만으로 경계를 정하면 대사 한복판에 칼이 들어간다. 규칙은 두 가지다.

- 사건 범위 안에서 대사를 끝낼 수 있으면 **끝까지 재생**한다
- 끝낼 수 없으면 그 대사가 **시작되기 직전으로 물러선다**
- 사건 범위는 저자가 정한 근사값이므로 **1.6초까지 넘어가도 된다**. 결말 차단선은
  절대 넘지 않는다

## 다섯 번째 규칙 — 해설은 조용한 곳에 놓는다

편집표가 자막을 읽어 **해설 블록을 조용한 구간으로 밀어 넣는다**. 건너뛴 영상은 앞의
영화 구간이 된다.

밀어내는 거리는 **10초**다. 45초까지 늘리면 겹침은 더 줄지만 건너뛴 영상이 그대로
늘어나 21.1분·해설 29%가 되어 승인 규칙을 벗어난다.

## 여섯 번째 규칙 — 편집표를 바꾸면 음성 값을 다시 치른다

세그먼트 수가 바뀌면 order가 밀리고, order별 문장이 달라지면
`generate_narration_audio.py`의 재사용 조건(order + 문장 일치)이 깨져 전량 재생성된다.

**해설 블록의 개수와 사건 순서가 같다면 번호만 옮겨 음성을 그대로 쓸 수 있다.** Devil에서
네 번 그렇게 했고 ElevenLabs 호출은 0회였다. 옮기기 전에 반드시 확인한다.

```python
old = [(order, event_id) for narration blocks in 이전 편집표]
new = [(order, event_id) for narration blocks in 새 편집표]
assert len(old) == len(new)
assert [e for _, e in old] == [e for _, e in new]   # 이게 참이면 번호만 옮기면 된다
```

렌더는 API 비용이 없다. **렌더만 다시 하는 수정은 얼마든지 해도 된다.**

## 일곱 번째 규칙 — 공용 프롬프트는 프로젝트마다 다르다

`prompts/narration_pass.md`는 "한국어 리뷰"이고 "해설을 덜어내라"는 지시다. 영어 리뷰에
해설 40%를 요구하는 프로젝트에 그대로 쓰면 **66개 중 4개만 해설로 쓰고 한국어로 나온다.**
실제로 그랬다.

프롬프트를 고치지 말고 `config.narration_pass_directives`에 프로젝트 지시를 적는다.
언어, 후보 사용 하한, 결말 금지 사항을 명시한다.

## 여덟 번째 규칙 — 측정 도구부터 의심한다

이번에 측정 도구가 세 번 틀렸고, 그때마다 잘못된 결론으로 갈 뻔했다.

- `-filter:a`와 `-af`는 **같은 옵션**이라 둘을 함께 넘기면 뒤의 것만 남는다. 다운믹스와
  더킹을 거치지 않은 원본을 재고 있었고, 11.6dB 여유가 있는 구간을 3.7dB로 읽었다.
- `measure_balance.py`가 **원본 mp3**를 재서 렌더가 적용하는 음성 게인을 반영하지
  않았다. 실제보다 4dB 좋게 보고했다.
- `cropdetect`는 밝은 영역을 보고하므로 **어두운 프레임 하나**에서 346x452를 반환한다.
  여러 지점을 재서 가장 넓은 값을 쓴다.

**수치가 기대와 다르면 대상보다 자를 먼저 확인한다.**

## 아홉 번째 규칙 — ffmpeg가 경고로 넘기는 것들

- `clip()`은 이 빌드에서 **NaN**이 되고, `volume`은 *"Invalid value NaN for volume,
  setting to 0"* 을 내며 **무음**을 만든다. 종료 코드는 0이다.
  `min(1,max(0,x))`를 쓴다. `mix_constantine_selected_voice.py`가 아직 `clip()`을 쓰므로
  그 아웃트로는 무음이었을 가능성이 높다.
- 음악 파일은 대개 앨범아트를 물고 있어 m4a로 뽑을 때 **`-vn`** 이 필요하다.
- `-filter_complex_script`는 ffmpeg 9.0에서 제거됐다. `-/filter_complex <file>`.
- `tile`에 입력을 여러 개 주면 **첫 장만 깔린다.** `concat` 후 `tile`.
- `drawtext` 레이블의 **콜론**은 옵션 구분자와 충돌한다. `3m20s` 형식을 쓴다.
- Windows **드라이브 문자의 콜론**이 필터 인자를 깨뜨린다. 상대 경로 + `cwd`를 쓴다.

## 열 번째 규칙 — 미리보기는 결과물과 같아야 한다

미리보기가 결과물과 다르면, 없느니만 못하다. 잘못된 결함을 보고 실제 결함을 놓친다.
Devil의 미리보기는 세 가지가 달랐다.

- 자막 두 트랙을 동시에 그렸다. 실제로는 해설 중 영화 자막이 억제된다.
- 해설 자막을 블록 7초 내내 그렸다. 실제로는 음성이 말하는 3~5초만 나온다.
- 클립 길이를 **계획값**으로 계산해 2.66초가 누적됐다. `-ss`는 키프레임에 붙으므로
  실제 인코딩 길이를 재야 한다. 11분쯤부터 입모양과 어긋나 보인다.

## 열한 번째 규칙 — 렌더가 만든 것에 맞춰 안내를 쓴다

`IMPORT_README.txt`가 "narration_audio의 음성을 오디오 트랙에 배치하라"고 안내하고
있었다. 음성이 빠진 마스터를 내보내던 시절의 문구인데, 지금 따르면 **나레이션이 두 번
들린다.** 안내문은 실제 산출물을 보고 생성한다.

같은 이유로 CapCut 프로젝트에는 오디오 트랙을 넣지 않는다. 마스터가 해설·효과음·음악을
모두 담고 있다.

## 열두 번째 규칙 — CapCut 초안의 함정

- CapCut은 폴더가 아니라 **`root_meta_info.json`의 `all_draft_store`** 를 보고 목록을
  만든다. 등록하지 않으면 보이지 않는다.
- `draft_ids`는 이름과 달리 **정수**다. 리스트를 넣으면 인덱스가 깨진다.
- `draft_content.json`의 **`id`가 곧 타임라인 id**이고 `Timelines/<id>/` 폴더 이름이다.
  새로 발급하면 목록에는 떠도 열리지 않는다.
- `draft_fold_path`는 **슬래시**, `draft_removable_storage_device`는 **빈 문자열**이다.
  드라이브 문자를 넣으면 외장 매체로 취급된다.
- `draft_content.json`, `template-2.tmp`, `Timelines/<id>/` 사본, 그리고 각각의 `.bak`이
  **전부 같은 내용**이어야 한다.
- **CapCut을 닫고 수정한다.** 초안을 메모리에 들고 있다가 종료할 때 다시 쓰면서 모르는
  키를 버린다.
- 자막 크기는 언어마다 다시 맞춰야 한다. 한국어 기준 `font_size 9.62`를 영어에 쓰면
  **49개 중 25개가 3줄**이 된다. 폰트 실측으로 2줄에 들어가는 최대 크기를 계산한다.

## 열세 번째 규칙 — 소리는 설정으로 빼고 측정으로 정한다

하드코딩된 값이 두 번 문제를 만들었다.

- 음성이 **`volume=1.0`** 으로 들어가 영화 대사보다 5.4dB, 영화 구간 전체보다 9.7dB
  높았다. `narration_voice_gain`으로 뺐고 -4dB에서 각각 +1.75dB, +6.05dB가 됐다.
- 해설이 빠진 블록이 **더킹 레벨 그대로** 재생됐다. 더킹할 음성이 없으면 영화 음량으로
  둔다.

마스터링은 렌더의 마지막 단계다. 클립별 믹스는 균형을 정하지만 전체 라우드니스는 정하지
못한다. `loudnorm`을 `linear=true`로 두 번 돌린다 — 동적 정규화는 조용한 구간과 큰 구간을
다시 균형 맞춰 더킹을 무너뜨린다.

## 새 영화 시작 절차

1. `<project>/config.json` — 해상도·CRF·다운믹스·언어·길이 한계·`narration_voice_gain`·
   `narration_pass_directives`·`master_loudness_lufs`
2. `scripts/copyright_probe.py` — 차단 여부를 먼저 본다. Constantine은 완성 후 전 세계
   차단됐다.
3. 참고 영상이 있으면 `scripts/analyze_reference.py`로 측정하고 규칙을 승인한다
4. `<project>/build_story_map.py` — 사건과 인과. 프레임으로 전부 확인한다
5. `<project>/build_edit_plan.py` — 그룹·예산·타일링
6. `scripts/run_workflow.py <project>/config.json run` 이후 지시를 따른다

`build_story_map.py`와 `build_edit_plan.py`만 영화마다 새로 쓴다. 나머지는 전부 공용이다.
